# 📋 Fitness Club Project Cheat Sheet

A concise reference guide for essential commands, workflows, and operations used across this project.

---

## 1. Virtual Environment Management

| Command | Description & Purpose | When to Use |
| :--- | :--- | :--- |
`source .venv/bin/activate` for mac
| `.\.venv\Scripts\Activate.ps1` | **Activate Environment:** Connects PowerShell to the project's isolated environment (indicated by `(.venv)` in the prompt). | At the start of each development session |
| `deactivate` | **Deactivate Environment:** Exits `.venv` and returns to the system-wide Python. | When finished or switching to another project |
| `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` | **Fix PowerShell Script Policy:** Permits running local scripts if PowerShell restricts execution. | One-time setup, only if `Activate.ps1` throws an execution policy error |

---

## 2. Server & Core Django Operations

| Command | Description & Purpose | When to Use |
| :--- | :--- | :--- |
| `python manage.py runserver` | **Start Dev Server:** Boots up the local development web server at `http://127.0.0.1:8000/`. Press `Ctrl + C` to stop. | To run and test the application or API endpoints |
| `python manage.py runserver 8080` | **Run on Custom Port:** Launches the server on port 8080 if port 8000 is occupied. | When encountering port conflicts |
| `python manage.py check` | **Validate Codebase:** Scans settings, model definitions, and system configurations for errors without running the server. | Before committing code or after major configuration changes |
| `python manage.py createsuperuser` | **Create Admin Account:** Prompts for username, email, and password to grant full access to `/admin`. | Initial setup for administrative dashboard access |
| `python manage.py shell` | **Interactive Django Shell:** Launches an interactive Python REPL with Django models and ORM preloaded. | For quick queries, debugging, or seeding test data |

---

## 3. Database & Migrations

Django models are translated into database tables through a two-step migration process: generate the migration plan, then apply it.

| Command | Description & Purpose | When to Use |
| :--- | :--- | :--- |
| `python manage.py makemigrations` | **Generate Migrations:** Scans `models.py` across all apps and creates migration files detailing database schema changes. | Immediately after modifying any model |
| `python manage.py migrate` | **Apply Migrations:** Executes pending migration files against the target database (`db.sqlite3` / PostgreSQL). | Immediately after running `makemigrations` |
| `python manage.py showmigrations` | **Inspect Migration Status:** Lists all migrations and marks applied ones with `[X]` and pending ones with `[ ]`. | To verify if pending migrations exist |
| `python manage.py sqlmigrate <app> <num>` | **Inspect Raw SQL:** Outputs the exact SQL queries generated by a migration without executing them (e.g., `sqlmigrate bookings 0001`). | To inspect generated indexes, constraints, and table definitions |

## 4. Modular Django Apps

| Command | Description & Purpose | When to Use |
| :--- | :--- | :--- |
| `python manage.py startapp <app_name>` | **Scaffold New App:** Generates a module folder containing `models.py`, `views.py`, `apps.py`, and `admin.py`. | When starting a new domain module (e.g., `bookings`, `gym_sessions`) |

> ⚠️ **Rule:** Every new app must be registered inside `INSTALLED_APPS` in `config/settings.py`.

---

## 5. Automated Testing

| Command | Description & Purpose | When to Use |
| :--- | :--- | :--- |
| `python manage.py test` | **Run All Tests:** Discovers and executes all test suites across the project inside an isolated test database. | Before merging changes or after introducing new logic |
| `python manage.py test <app_name>` | **Run Targeted Tests:** Runs tests specifically for a given application (e.g., `python manage.py test bookings`). | During focused feature development |

## 6. Git Version Control Essentials

| Command | Description & Purpose |
| :--- | :--- |
| `git status` | Displays the state of working directory and staged changes. |
| `git diff` | Shows line-by-line differences of unstaged changes. |
| `git add .` | Stages modified and newly created files (ignoring files defined in `.gitignore`). |
| `git commit -m "feat: description"` | Commits staged changes with a standardized message. |

## 💡 Daily Development Routine

A standard sequence when starting work on the project:

```powershell
# 1. Activate virtual environment
.\.venv\Scripts\Activate.ps1

# 2. Run the development server
python manage.py runserver

# 3. (When updating models) Create and apply migrations
python manage.py makemigrations
python manage.py migrate

# 4. Run automated tests
python manage.py test
```
